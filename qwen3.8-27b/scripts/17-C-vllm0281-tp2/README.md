## 目标与验收合同

在已安装海光驱动的 K100-AI 主机上，使用真实的 OpenDAS vLLM 0.28.1 发行线运行现有 BF16 权重。复用拉起包的 `up.sh → common/launch.sh → S3–S8`，不建设第二套生命周期，不改动 01、13 或旧 vLLM 线。

通过需要同时满足：

1. 镜像内发行元数据的 vLLM release 为 `0.28.1`，保留完整 rc/dev/local 后缀和插件身份；不通过改名、覆盖版本值或换成 0.29.0 冒充目标版本。
2. 正式入口的 Worker 快照为 READY，包版本、line、launch_id、端口、模型目录与实际容器互证，`/v1/models` 可用。
3. 实际请求能正确完成普通问答、确定答案的计算、工具调用、重复长前缀检索和流式输出；返回 200 或出现 token 本身不算语义通过。
4. 预算内场景完成后没有本次推理产生的 VMFault、未处理 Traceback 或崩溃重启；保留原始请求、响应、日志和最终运行身份。

本线不承诺 1M 上下文、比 SGLang 更快、完整模型精度评估或生产全量验收；不修改权重与标准性能量具，不安装或热重载宿主驱动，不重启宿主。

公开插件源码参考固定为 `HYGON-AI/vllm-plugin-das@2a27545243a3818f1c771cdf0cbcc974e8b39568`，其目标为 `0.28.1rc1.dev491` release 线。只有遇到有证据的兼容缺陷时才考虑在本任务隔离镜像内构建匹配插件；不把主机或原镜像原地升级为通用 PyPI 环境。

### 唯一量具与数据解释

- 只使用包内未修改的 `bench/standard_load.py`，通过正式 `up.sh benchmark` 调用；须与源码量具核对 SHA256。按 `CYCLES=1` 完成一次 45K–350K 周期，不能把默认两周期或按时长跑误报为一次完整周期。
- 固定原默认 `seed=7`、`temperature=0.7`、`top_p=0.8`、SSE usage 和性能轮次的 `ignore_eos=true`；保持标定、700／1200／2000／3500-token 探针、常态输出分布与新前缀逻辑。量具不注入 `enable_thinking=false`，不能混用先前功能验证的关闭 thinking 请求设置。
- 不同时运行其它模型负载；各实例 JIT 缓存独立，不借用 01／13 的编译产物。保留实际预热状态；量具第一轮全新前缀的成本与后续缓存命中矩阵分列，不能称为完全相同的编译冷启动。
- 自证表全部达标且完整周期结束后，才使用四指标矩阵。保留实际输入／输出长度、样本数、失败和超范围样本；不为了报告达标改量具或挑轮次。标准矩阵的最后输入档没有硬性 350K 上界，边界超出须另外披露，不静默算成严格范围内样本。
- TTFT 从首个 content 或 reasoning 片段计时；prefill 为总输入／TTFT，decode 为 completion token／解码时间。命中率可能由前轮深度估算，不等于服务端实际命中；不能把高命中 prefill 数字当作纯未缓存计算速度。
- 同 seed 仍可能因采样输出、时间标记及历史追加得到不同文本与实际深度。按实际输入深度与输出规模分桶比较中位数、样本数及分布，不宣称逐请求配对、统计显著性或已排除全部外部干扰。
- 历史对照须明确时间差，不冒称同时段对照；没有合格的完整周期与自证表时，不给出完整性能矩阵或采用结论。

### 执行前置与验收边界

性能对照前须核对真实 1M 配置和 tokenizer 字节身份、农场链接目标、已安装 CLI 能力及模型切分约束。1M 配置使用既有 YaRN／`max_position_embeddings=1000000`，不另写缩放参数；24 个 attention heads 可按 TP4／TP8 整除，TP8 的 4 个 KV heads 由当前核心原生复制。配置／索引／tokenizer 摘要须与历史参照一致；权重复用原链接，不重写。静态约束成立不代替实机初始化。

每线须分别完成局部配置／版本回归、单线打包及 MANIFEST／量具校验，并通过正式 `start/state/stop` 验证入口与归属。实机性能检查应先 READY、身份／版本／实际配置互证，并完成有限功能和标准请求字段检查，再进入标准周期；TP8 继续受既有跨 socket／运行驱动 v4 门禁约束，不增设绕过开关。

初始化不支持、显存容量不足、缺少可证明一致的模型配置或到达执行时限时，应保留失败证据；不关闭已声明的 MTP／前缀功能、不换量化精度、不降低标准负载、不改引擎或热重载驱动来制造通过。独立配置的结果分别解释，不以其中一线代替另一线的验证。

发布完整性能结果时，需提供实际包／launch／容器／模型身份、量具摘要、完整周期原始数据和四指标矩阵，并明确历史对照或新现场对照；公开源码与有限验证状态不表示这些条件已经满足。1M 是配置上限目标，350K 标准负载通过也不证明满 1M 请求、长文本精度、长期压力稳定性或 A3 最终保障门。
