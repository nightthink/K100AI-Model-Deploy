# K100AI 模型部署实践

[MIT License](LICENSE)

海光 **K100-AI（gfx928，8×64GB）** 上的大模型部署配置源码与**完整拉起包**发布仓。
保留既有精选拉起包，也可公开明确标注验证边界的实验配置源码；有限功能、完整性能、长期稳定性与生产适用性分别说明。
源码公开不等于通过全部验收，实验配置不作为生产推荐；内部调优过程、施工预算与私有运行日志不在本仓。

18／19此前各一次标准负载在7200秒执行时限到达时结束，没有取得合格完整性能矩阵；不能把“模型已初始化且能推理”写成“完整性能通过”，也不能把“标准周期未完成”写成“模型不能运行”。超时根因尚未确定，不发布相对 SGLang 的速度收益结论。

## 七条既有线怎么选（详见 [qwen3.8-27b/scripts/README.md](qwen3.8-27b/scripts/README.md)）

| 线 | 定位 | 卡数 | 关键实测 |
|---|---|---|---|
| **13** ★ | **推荐主力**：bf16 TP8 全 P2P + custom-AR（01 线的直系八卡版） | 8 | 单流 decode 62.1 tok/s；冷启 prefill 2665（80-150K 字符）/ 1601（≥350K） |
| **01** ★ | bf16 全精度 + 1M 上下文（v2：0828树+AR），四卡首选 | 4 | 短代码 31.5-32.8 / 长文 26.2 / 120K 26.5-29.5（较 v1 全面 +30~60%） |
| 02 | bf16 双副本 + 粘性网关 | 8 | 聚合 prefill 2.91× / decode 2.55× |
| 11 ⛔ | 深上下文（INT8+DFlash2+custom-AR） | 4 | 120K 暖 decode 53-77（峰 108）；1M 上下文 |
| 10 ⛔ | 高 QPS（INT8 无投机） | 4 | 8 路聚合 242.6 tok/s；prefill 3990 |
| 09 ⛔ | 低延迟（11 的前身，短上下文最快） | 4 | 单流 86 tok/s（代码类，瞬时 105-113） |
| 12 ⛔ | 社区栈对照线（v1.3.1 整包，离线镜像） | 4 | 与 11 同源同内核（二进制逐字节对照证实）；原「冷 prefill 1.6×」已证伪为采样噪声——生产选型请用 11 |

> ### ⛔ 2026-09-11：INT8 全系（09/10/11/12）暂不可投产
>
> VMFault 两次复现（存活 19 分 26 秒 / 37 分钟），均在**低负载、显存充裕**时发作，无一致前兆。
> 上表 INT8 各行的性能数据本身有效，但**不要用于生产**；bf16 的 13/01/02 线不受影响。
> 各线 README 首部有同样警示。14 线（INT8 TP8）因此从未发布。

**13 vs 01 同口径实测**（各约 2 小时，编程助手真实负载，先验明两线 S3 命中率可比：92.7% vs 92.5%）：
单流 decode **+77%**、冷启 prefill 80-150K **+52%** / ≥350K **+71%**、≥350K 的 TTFT −41%。
规律是**输入越长 TP8 优势越大、并发越高相对优势越小**；四卡场景仍选 01。

## 拉起包怎么用

```bash
# 直接取 Releases 里的现成包（或仓库侧 cd qwen3.8-27b && bash build_package.sh 13）
tar xzf q38-kit-13-*.tar.gz && cd q38-kit-13
bash up.sh start    # 01/13/17/18/19：快速触发后台生命周期，不等待就绪
bash up.sh state    # 无副作用查询；STARTING(20)继续观察，READY(0)才是就绪
bash up.sh stop     # 按本包归属证明定点停止，不清理未知资源
```

上述用法适用于01／13／17／18／19，其余线按各自README使用；详情见
[`拉起包使用说明`](qwen3.8-27b/docs/拉起包-使用说明.md)。`start`返回`STARTING`不是失败，也不等于已就绪。
Release包对应各自标签版本，不会随`main`自动更新；需要当前源码版本时，请在`qwen3.8-27b/`运行打包器。

通用前提包括DCU驱动已装载（`/dev/kfd`、`/opt/hyhal`）及镜像／权重可获取；
网络不可达时按各线README离线准备。额外模型资产、卡组和运行驱动要求以各线说明为准，不能将“网络可达”当作实验线已具备全部前提。

## 发布纪律

- 完整拉起包验收仍按「解包 → up → S1-S8 → 真实请求 → 完整停止」执行；验收结论对应具体版本与场景，不自动覆盖后续源码变更。
