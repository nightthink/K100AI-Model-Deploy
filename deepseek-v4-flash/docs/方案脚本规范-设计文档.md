## 一、分层：三层，复用粒度不同

搞错层次就会重复劳动。今天给 验证机B 装环境时，我就把 L1/L2 的活重做了一遍。

| 层 | 粒度 | 内容 | 谁来做 |
|---|---|---|---|
| **L1 机器层** | **每台机器一次**（且需持久化 / 开机自愈） | 内核参数、PCIe、驱动、固件 | 系统服务（systemd） |
| **L2 配置层** | **每个「线路 + 配置」一份** | 挂载、补丁、容器环境、启动命令、就绪判据、自证、收尾 | 配置脚本 |
| **L3 部署层** | **每个对外服务一份**（可聚合多个 L2 实例） | 网关、端口、负载均衡、粘性路由 | 部署脚本 |

> L1 会**悄悄失效**（重启、驱动重载），所以 L2 每次启动前必须重新断言 L1 的后置条件，
> 而不是信任「当初设过了」。这是本规范的核心。

## 一·五、执行载体是**正交维度**，不是阶段

**容器只是一种载体。** 换 NVIDIA 卡时很可能直接裸机起 vLLM，不进容器；
也可能是 systemd unit、k8s Pod。阶段定义**契约**，载体决定同一契约**怎么落地**。

> 阶段名里**不允许出现「容器」二字**。凡是写死容器的地方，都是把实现当成了抽象。

| 契约动作 | 容器载体 | 裸机载体 | systemd 载体 |
|---|---|---|---|
| 构造运行环境 | `-v` 挂载 + `-e` 环境变量 | venv/conda + `export` + 补丁文件就位 | unit 的 `Environment=` / `BindPaths=` |
| 清理上一实例 | 按名 `stop` → `rm` | 按 PID/端口 kill + 等端口释放 | `systemctl stop` |
| 拉起 | `docker run` entrypoint | 直接 `exec python -m ...` | `ExecStart=` |
| 存活/失败判定 | `docker inspect .RestartCount` + `.State` | 进程存活 + 由 supervisor 提供重启计数 | `systemctl show -p NRestarts,ActiveState` |
| 日志可读 | `docker logs`（宿主可读） | 重定向到宿主路径 | journald |
| 收尾 | `update --restart=no` → `stop` → `rm` | `SIGTERM` → 等 → `SIGKILL` | `systemctl stop` |
| 资源归还判据 | 显存回落 + 无孤儿上下文 | **同左**（与载体无关，只与驱动有关） | 同左 |

**要点**：最后一行说明了一件事——**资源归还判据属于硬件/驱动维度，不属于载体维度**。
两个维度要分开，否则换载体时会误删掉本该保留的判据。

脚本实现上，载体差异应收敛到一组**载体适配函数**（`carrier_start` / `carrier_stop` /
`carrier_alive` / `carrier_logs` / `carrier_restarts`），各阶段只调这组函数，不直接写 `docker`。

## 二、十个阶段与各自的契约

每个阶段都要能回答四个问题：**前置条件 / 保证什么 / 怎么验 / 失败怎么办**。
只有这四问齐全，它才是契约而不是一串命令。

### S1 · 机器级准备（L1）

| | |
|---|---|
| **保证** | 内核参数与 PCIe 处于既定状态，且**开机与驱动重载后能自愈** |
| **判据** | 逐项读回实际值比对，不看「服务是否 exit 0」 |
| **失败** | 拒绝进入 L2 |

- **通用**：内核参数持久化；「设置」与「校验」必须是两个独立动作
- **硬件耦合（海光）**：
  - PCIe ACS 清除 —— ACS 本身是通用 PCIe 概念，但**「hycu 驱动加载时会把所有桥的 ACS 重新打开（`ACSCtl=0x1D`）」是海光特有**，因此清除必须**等 hycu 绑定完全部 GPU 之后**（`acs_clear_guarded.sh`，判据是 `/sys/bus/pci/drivers/hycu/0000:*` 计数）
  - 判据不能用 KFD 拓扑节点数（早早填好）或 `/dev/dri/renderD*` 计数（rmmod 后 udev 删得慢）
- **当前为空**：固件/微码统一（实测八卡 mp1 均为 15.7.0，无操作面）

> **事故索引**：`numa_balancing` 重启失效未被发现；`acs-clear.service` 报成功而 19 小时后 ACS 已被驱动改回。

### S2 · 宿主环境（L1）

| | |
|---|---|
| **保证** | 执行账号具备所需权限；宿主侧依赖就位 |
| **判据** | 能力探测，而非假设 |
| **失败** | 拒绝启动 |

- **通用**：容器运行时可用性、权限探测
- **实现要点**：账号可能不在 `docker` 组但有 `sudo NOPASSWD` ——
  脚本一律 `if docker info >/dev/null 2>&1; then DOCKER=docker; else DOCKER="sudo docker"; fi`，
  **不要因为权限问题绕路去改文件位置**

> **事故索引**：验证机B 上 `docker save|load` 报 `permission denied ... docker.sock`。

### S3 · ★ 起跑前的前提校验（gate，L2 每次启动）

**这是本规范新增的核心阶段，S1 有没有做过不代表现在还成立。**

| | |
|---|---|
| **前置** | 无 |
| **保证** | 所有前提在**此刻**成立 |
| **判据** | 全部读回实际值 |
| **失败** | **拒绝启动**，打印哪一项不满足 |

断言清单（当前实现）：

| 断言 | 类别 |
|---|---|
| `kernel.numa_balancing == 0` | 通用 |
| ACS 置位桥数 `== 0` | 硬件耦合（海光/PCIe） |
| 绑定到 hycu 的 GPU 数 `== 期望值` | 硬件耦合（海光） |
| 目标卡组同 socket / 同型号 | 硬件耦合（本机异质：卡 4/5/6 是 `0x6211`，350 W） |
| 镜像存在、模型路径存在且软链无断链 | 通用 |
| 依赖产物存在（如 `dlhook2-sg.so`） | 硬件耦合（活锁绕法） |
| 无他人容器占卡、无孤儿 KFD 上下文 | 通用（KFD 名字是海光/ROCm 的） |

### S4 · 运行环境构造：挂载 / 补丁 / 环境变量（L2）

| | |
|---|---|
| **保证** | 运行环境的文件系统与环境变量符合配置意图 |
| **判据** | 启动后**读回实际生效的** env 与挂载（容器用 `docker inspect`，裸机读 `/proc/<pid>/environ`）|
| **失败** | 视为配置错误，不重试 |

- **通用**：模型与缓存挂载、可复现的环境变量集合
- **硬件耦合（海光/ROCm）**：`--device=/dev/kfd,/dev/dri,/dev/mkfd`、`-v /opt/hyhal`、
  `HSA_*` / `NCCL_*` / `HIP_VISIBLE_DEVICES`、`LD_PRELOAD=dlhook2*.so`
- **注意**：在容器载体下 S4 与 S6 物理上是**同一条 `docker run`** 的两半（前者 `-v`/`-e`，后者 entrypoint 之后）；
  在裸机载体下则是「先 export/就位，再 exec」。
  分开写是因为**变更频率不同**——补丁挂载稳定，模型参数常调。

> **事故索引**：单引号串里 `${YARN_FACTOR:-4.0}` 不展开，字面量进了 JSON，容器秒退。
> 凡是要展开变量的 JSON，必须 `'"$VAR"'` 跳出单引号，并离线验证 JSON 合法。

### S5 · 清理上一实例（L2）

| | |
|---|---|
| **保证** | 无残留、资源已释放 |
| **判据** | 按**真实实例标识**查（容器名 / PID / 端口占用）、显存回落到基线、孤儿 KFD 为 0 |
| **失败** | 拒绝启动 |

- **通用**：清理同标识残留、等待资源释放
- **实现要点**：**清理时用的标识必须与 S6 实际创建的标识一致**——
  容器载体下是容器名，裸机载体下是 PID 文件或监听端口

> **事故索引**：`docker rm -f q38-tp8` 而实际创建的是 `q38-tp8h`，残留删不掉；
> 另有一次被 15 小时前的同名旧容器骗了 8 分钟。

### S6 · 启动命令（L2）

| | |
|---|---|
| **保证** | 以既定并行拓扑与算法配置拉起推理服务 |
| **判据** | 见 S7 |
| **失败** | 见 S7 |

- **通用**：并行度、上下文长度、投机解码、解析器
- **硬件耦合**：并行拓扑的**可行性**由硬件决定（例：C 线 TP4 装不下 1M；
  PP 与投机解码互斥；sglang 的 custom all-reduce 走 aiter，在 K100-AI 上去掉
  `--disable-custom-all-reduce` 会 SIGSEGV）
- **规范**：**互斥关系必须前置成静态检查**，不要靠运行时崩溃来发现

### S7 · ★ 就绪 / 失败 / 进度（L2）

| | |
|---|---|
| **保证** | 能**在实例外部**判定三种状态之一：就绪、失败、进行中 |
| **判据** | **就绪** = HTTP 200；**失败** = 崩溃重启计数 > N，或容器退出 |
| **失败** | 立即返回并打印根因，不等满超时 |

- **通用**：三态判定；日志落**外部可读**路径；进度可 grep
- **必须点名**：**凡是带自动重启的载体**（容器的 `--restart`、systemd 的 `Restart=`、
  裸机的 supervisor），**崩溃重启循环看起来与「还在启动」完全一样**。
  必须监视重启计数——容器 `docker inspect -f '{{.RestartCount}}'`，
  systemd `systemctl show -p NRestarts`，裸机由 supervisor 提供。

> **事故索引**：c-tp4 崩溃 9 次，脚本仍在等，要 65 分钟才超时；
> 修复后 c-tp8 的失败在 1 分钟内被捕获并打印根因。

### S8 · ★ 运行时自证（attestation，L2）

**S7 问「起来了吗」，S8 问「起来的是不是我们要的那个」。**

| | |
|---|---|
| **保证** | 声明的优化确实生效，关键容量确实达标 |
| **判据** | 从服务日志 / inspect 读取**证据**，而非信任配置 |
| **失败** | 判定为「配置未生效」，数据不可用于结论 |

自证清单（当前实现）：

| 自证项 | 证据 | 类别 |
|---|---|---|
| agent 过滤真的生效 | 日志出现 `→保留4个`（不能只看 `LD_PRELOAD` 设了） | 硬件耦合 |
| KV 池实际容量 | 从日志实读（vLLM `GPU KV cache size:` / sglang `max_total_num_tokens`），**不写死** | 通用 |
| 投机解码启用与接受率 | `speculative_config` + `acceptance length` | 通用 |
| 内核路径无回落告警 | `config not found ... using default {'num_warps': 1}` | 硬件耦合 |

> **事故索引**：`LD_PRELOAD` 失败是静默的。若不查 `→保留4个`，测到的是活锁中毒路径，
> 而我们会把它当成「我们能达到的最好水平」。

### S9 · ★ 收尾与资源归还（L2）

| | |
|---|---|
| **保证** | 资源完全归还，不影响下一个实例 |
| **判据** | 容器消失 **且** 显存回落 **且** 孤儿 KFD 为 0 |
| **失败** | 告警并阻止下一阶段 |

顺序（先解自动重启，再停，再删，最后等资源）：
- 容器：`update --restart=no` → `stop` → `rm` → **轮询等资源回落**
- 裸机：解除 supervisor 托管 → `SIGTERM` → 等 → `SIGKILL` → **轮询等资源回落**

**最后一步与载体无关**，只与驱动的显存归还行为有关。

- **通用**：优雅停止、等待资源释放
- **硬件耦合**：`docker rm -f` 会让 hycu 漏显存（残留 57 GB 而 `ps` 无进程，
  孤儿 KFD 等 4 分钟也不消失）

> **事故索引**：不解重启策略就 `stop`，容器又被拉起来。

### S10 · 网关 / 负载均衡（L3）

| | |
|---|---|
| **保证** | 单一入口；多副本时兼顾**粘性**与**均衡** |
| **判据** | 粘性 / 分散 / 会话头 / 流式 / 工具调用 五项 |
| **失败** | 回退到直连单副本 |

- **通用**：反向代理、路由策略、健康检查
- **实现要点**：必须**同时**做粘性与均衡——不粘则每副本各付一次冷 prefill（4 倍代价），
  纯哈希在小 N 下会偏斜到 11:21（吞吐 612 → 393）

## 三、硬件耦合点清单（换硬件要改的全部）

> 注意与**载体维度**分开：本表是「换 GPU / 换驱动」要改的；
> 「换容器→裸机」要改的在 §一·五 的载体适配表。两者互不影响。

| 耦合点 | 依赖的硬件事实 | 换到别家 GPU 时 |
|---|---|---|
| ACS 清除 + hycu 绑定时序 | hycu 加载会重开 ACS | 多数平台无此问题，S1 相应项可空 |
| `dlhook2*.so` agent 过滤 | 跨 socket VRAM IPC 触发 hycu evict↔restore 活锁 | 无此缺陷则整项删除 |
| `/dev/kfd` `/dev/dri` `/dev/mkfd` `/opt/hyhal` | ROCm/DTK 设备与运行时 | 换成对应的容器运行时集成 |
| 孤儿 KFD 上下文检测 | KFD 显存回收行为 | 换成对应的显存归还判据 |
| 卡型号 / 功率上限异质检查 | 本机混插 `0x6210`（480 SIMD/400 W）与 `0x6211`（512 SIMD/350 W） | 按实际拓扑重写 |
| 并行拓扑可行性 | 显存容量、互连带宽 | 重新实测，不可照搬 |

- **多机编排**（L3）：目前单机。S10 的网关天然可扩到多机，接口不变
